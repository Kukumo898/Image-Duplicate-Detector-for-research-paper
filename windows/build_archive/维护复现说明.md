# 维护与源码位置

应用 Python/HTML/CSS/JS 源码位于 `../release_source/`，生命周期、缓存目录归属、备份恢复工具位于 `../tools/`。当前目录包含两个外层入口、内层图形入口和迁移桥接的源码，以及合成演示图生成器。

外层两个 EXE 使用同一个 `DeliveryEntry.cs` 编译，根据文件名选择启动或迁移界面。内层 `TujianLauncher.cs` 保持原启动逻辑，只把备份/恢复/帮助菜单指向外层入口。Windows 自带 .NET Framework 4.x 的 csc 编译器用于构建，用户使用时不需要编译或安装 Python。

示例（维护人员在停止的干净包上执行）:

```powershell
# 从本“维护资料”目录执行；中文命令脚本请保存为 UTF-8 BOM。
$compiler = Join-Path $env:WINDIR 'Microsoft.NET\Framework64\v4.0.30319\csc.exe'
& $compiler /nologo /target:winexe /platform:x64 /codepage:65001 /out:..\..\启动图片查重系统.exe /win32icon:..\tujian-liquid-glass-v1.ico /resource:tujian-liquid-glass-v1.png,tujian.png /reference:System.Windows.Forms.dll /reference:System.Drawing.dll /reference:System.Web.Extensions.dll DeliveryEntry.cs
```

同样编译 `迁移数据.exe`；将源码改为 `TujianLauncher.cs`、输出改为 `../图片查重系统.exe` 则构建内层入口。重新构建后必须同步 source_manifest、outer_manifest、file_manifest 的实际哈希，不能跳过校验或直接覆盖正在运行的用户包。`build_layout.py` 是本次从历史干净包构建的归档脚本，其历史目录引用不是用户运行依赖。

`layout_migration.py` 调用原有校验和恢复逻辑，不修改科学算法。备份兼容依据是应用源码及依赖锁的精确清单，不能通过删掉校验来迁入不匹配旧版本。

图标由内置 imagegen 生成，原图在 `icon-master.png`。本包没有替项目自主代码选择开源许可证；第三方许可及进一步发布要求见 GitHub发布说明.md。这些材料是源码归档，不应被误解为已完成所有第三方对应源码提供义务。
